## 1. 概要

指示書14の完了照合（設計チャット25・コンセプト＋エウレカ機能検査会議）で、シム実測の
下降跨ぎ（マルチボールペース）の値が器具として不適格と自己訂正された（チャット25 #10）。
これを受け、較正用プロトタイプ（`proto/ring_keep_calibration.html`）のマルチボール模擬
デフォルトをB1帯由来へ変更し（作業1）、噴出模擬発生器にのみオンセット遅延を新設した
（作業2・精密化#9「猶予の対象は無偽装イベント〈噴出・自球突破〉のみ」）。あわせて報告14
照合時に判明した不備2件（追補A・B）へ対応し（作業0-1-2/1-3）、NOW文書をv1.6→v1.7へ
更新した（作業3）。`ring_sim.py`は本指示書を通じて0差分。

## 2. 追補A・B（報告14の不備2件への対応）

チャット25 #8「報告14照合：合格（条件付き）。不備2件（作業3-5テレメトリの実施報告
なし／模擬発生間隔スライダー反映の検証ログなし）→指示書15作業0で追補」への対応。

### 2-1. 追補A：作業3-5テレメトリの実施報告

指示書14の作業3-5で追加したはずの球数テレメトリ（`ball_count_max`・`ball_count_mean`・
`ball_count_overflow_frac`・`ball_count_overflow_threshold`）が、報告14本文で実施報告
されていなかった不備。実装自体は既に存在することを`proto/ring_keep_calibration.html`
1398〜1401行で確認済み：

```js
ball_count_max: s.ballCountMax,
ball_count_mean: s.ballCountSamples ? Number((s.ballCountSum / s.ballCountSamples).toFixed(3)) : 0,
ball_count_overflow_frac: s.ballCountSamples ? Number((s.ballCountOverflowSamples / s.ballCountSamples).toFixed(4)) : 0,
ball_count_overflow_threshold: BALL_COUNT_OVERFLOW_THRESHOLD
```

出力JSON（セッション終了ボタン）の`config: s.config`と並んで4フィールドとも実装済み・
実装漏れなしを確認した。**実装の欠落ではなく報告書への記載漏れ**（今回の指示書15報告で
遡って明記する）。

### 2-2. 追補B：模擬発生間隔スライダー反映の検証ログ

スライダー変更が実際に`freshState()`の`s.config`へ反映されることを、`window.__calibTest`
経由で機械検証した（詳細ログは§4-2に統合。噴出・マルチボール・外来アイテムいずれも
スライダー値どおりに`eruptionIntervalSec`／`multiballIntervalSec`／
`itemArrivalIntervalSec`へ反映されることを確認）。

## 3. 作業1：マルチボール模擬デフォルトのB1帯由来化

**チャット25 #10（自己訂正）逐語**：「下降跨ぎn=261/1,000試行≒0.07回/世界セッション。
『中央値25tick』はバースト内間隔であり到来率ではない。シムはB1器具から再割当済（v1.2）
のため下降率は信用不可。マルチボール到来の実態はB1帯由来（2〜10回/セッション≒
126〜630秒間隔）で見るべき」。

これを受け、マルチボール間隔スライダーの既定値・範囲を変更した：

| 項目 | 指示書14時点 | 指示書15後 | 根拠 |
|---|---|---|---|
| 既定値 | 35秒（シム下降跨ぎ中央値。**不採用**） | **210秒**（B1帯中央=6落球/セッション≒1260s/6） | チャット25 #4・#10 |
| スライダー範囲 | 1〜400秒 | **120〜650秒**（B1帯両端126〜630秒をカバー） | チャット25 #4 |
| 外来アイテム間隔 | 57秒 | 57秒（**据え置き**） | アイテム取りこぼし代理指標は器具として有効なまま（下降跨ぎとは別指標） |

上昇跨ぎ（噴出）の値（既定8.4秒）は器具として有効なままであり、変更していない。

## 4. 作業2：噴出模擬発生器のオンセット遅延

### 4-1. 実装

**チャット25 #1**：「即時観測化を許さない。偽前提の猶予≥約1分」。
**チャット25 #6精密化（逐語）**：「猶予の対象は無偽装イベント〈噴出・自球突破〉のみ。
偽装済みイベント〈マルチボール・外来アイテム〉は序盤から流れてよい」。

噴出模擬発生器**にのみ**オンセット遅延スライダー（`eruptionOnsetDelay`・既定**60秒**・
範囲**0〜300秒**）を新設し、`proto/ring_keep_calibration.html`946行台の`step()`関数内で
以下のとおり実装した（マルチボール・外来アイテムのタイマーは変更していない）：

```js
s.multiballSpawnTimer -= dt;                    // ← 無条件（変更なし）
if (s.multiballSpawnTimer <= 0) { ... }

if (s.elapsedSec >= c.eruptionOnsetDelaySec) {   // ← 噴出のみ遅延ゲート（新設）
  s.eruptionSpawnTimer -= dt;
  if (s.eruptionSpawnTimer <= 0) { ... }
}

s.itemArrivalSpawnTimer -= dt;                   // ← 無条件（変更なし）
if (s.itemArrivalSpawnTimer <= 0) { ... }
```

遅延中は噴出タイマー自体を進めない設計とした（遅延明けの瞬間に溜まった分が一斉発火
することを避けるため。遅延終了後は通常のジッター付き間隔で1件目が発生する）。

### 4-2. 機械検証（成功/失敗パス分離。§9-c）

`window.__calibTest.freshState()`で独立したシミュレーション状態を生成し、`step()`を
手動ループで刻んで検証した（画面上の実行中セッションとは独立。ブラウザタブのDOM/canvas
アニメーションループには一切触れない）。

| 検証 | 条件 | 結果 | 判定 |
|---|---|---|---|
| 噴出は既定遅延（60秒）より前に発生しない | eruptionOnsetDelay=60s・eruptionInterval=8.4s・0〜30秒を1/60秒刻みで実行 | 噴出発生数=**0件**（30秒間） | 成功パス |
| 噴出は遅延明け後、通常のジッター付き間隔で発生する | 同上設定・0〜90秒を実行 | 初回噴出=**68.4秒**（60s+ジッター相当。期待範囲66.7〜70.1秒に整合。実装時の別試行では70.2秒を記録済み〈作業コミットメッセージ参照〉） | 成功パス |
| 外来アイテムは遅延の影響を受けない | itemArrivalInterval=1s（下限）・eruptionOnsetDelay=60s維持・0〜30秒を実行 | 初回到来=**0.82秒**（60秒を大きく下回る） | 成功パス（遅延非適用の直接証明） |
| マルチボールは遅延の影響を受けない | multiballSpawnTimerを0.05秒に強制設定・eruptionOnsetDelay=60s維持・0〜10秒を実行 | `multiballArrivedCount`=**1**（60秒を大きく下回る10秒未満で到来） | 成功パス（遅延非適用の直接証明） |
| スライダー変更が`s.config`へ反映される（追補B） | eruptionInterval/eruptionOnsetDelay/multiballInterval/itemArrivalIntervalの4スライダーを`el.value`で明示変更後に`freshState()` | 初期`multiballSpawnTimer`≈246.8（`nextSpawnDelaySec(210)`の±20%ジッター範囲168〜252内）等、全4値がスライダー値を正しく反映 | 成功パス |

いずれも失敗パス（噴出が遅延前に発生する・マルチボール/アイテムが遅延の影響を受ける・
スライダー変更が無視される）とは明確に異なる出力になることを確認済み。

## 7. 裁量事項

- **マルチボール間隔既定値の算出**：「B1帯中央=6落球/セッション」からの210秒導出は
  900tick≒1260秒セッションを6等分した近似値（1260/6=210）。チャット25 #4・#10の
  「2〜10回/セッション≒126〜630秒間隔」という記述と整合する範囲内の裁量選定
- **噴出オンセット遅延の実装位置**：「遅延中はタイマー自体を進めない」設計（遅延明けの
  瞬間に溜まった分の一斉発火を避ける）は指示書15本文に明記がなかったための裁量。
  対案（タイマーを遅延中も進め、遅延終了時点で溜まっていれば即発火）は「一斉発火」の
  不自然さがあるため採らなかった
- **追補Aの扱い**：報告14照合で「実施報告なし」と指摘されたテレメトリは実装自体が
  既に存在していたため、追加実装はせず本報告書での記載追記のみで対応した（実装漏れが
  あれば追加実装が必要だったが、確認の結果不要と判断）
- **NOW第25節の統合範囲**：指示書14・15を単一の節（第25節）にまとめた（指示書13までは
  1指示書=1節の対応だったが、14・15は同一の「ペース密度器具整合」というテーマの
  前半・後半にあたるため、節を分けるより一体として読める形を優先した）
