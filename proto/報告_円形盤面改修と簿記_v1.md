## 3. 作業1：円形幾何の実装（プロト）

`proto/ring_keep_calibration.html`の物理エンジンを、矩形AABB方式（パドル下部固定・
上部ブロック矩形グリッド）から、円形盤面（外周=壁帯・中心=穴）へ全面的に書き換えた。

| 要素 | 実装 |
|---|---|
| 盤面 | 円形。半径`BOARD_R=250px`。外周付近を2リング×16角度セクタの同心円壁帯とした |
| 重力 | 全域・中心向き・一定加速度（`gravity_accel`）。1/r²等の距離依存は不採用（指示書12§2の指示どおり。中心近傍の速度発散防止） |
| パドル | 中心穴を中心とする固定半径（`paddle_orbit_r`）の円軌道上を角度方向にのみ移動。マウス位置の「盤面中心からの角度」を目標角として追従する |
| 落球 | 中心穴（半径`hole_r`）への到達＝出口専用。穴から出てくるものは無い |
| サーブ | パドル位置から外向きに射出（指示書12§2の例をそのまま採用） |

**パラメータ初期値と選定根拠**：

| パラメータ | 初期値 | 選定根拠 |
|---|---|---|
| `gravity_accel` | 220px/s² | 既定ボール速度260px/sに対し、軌道が明確に湾曲しつつもパドルから壁帯まで到達可能な大きさとして選定（裁量。スライダーで対話的に再調整可能） |
| `hole_r` | 40px | 盤面半径250pxの約16%。小さすぎると落球がほぼ起きず、大きすぎるとパドル軌道帯を侵食するため中間的な値とした |
| `paddle_orbit_r` | 105px | 穴半径40pxと壁帯内縁170pxの中間帯（指示書12§2「盤面半径の中間帯」の指示どおり）。穴に近い小半径にすると角度被覆（弧幅/円周比）が過大になり穴上キャンプで防御が自明化する懸念があるため、これを避けた |
| パドル弧の半角（拡大0段） | 約0.43rad（≈24.5°） | 旧矩形版パドル幅90px（半径105pxでの弧長換算）を踏襲 |

すべて`gravity_accel`・`hole_r`・`paddle_orbit_r`はスライダーとして実装し、対話的に
調整・較正できるようにした（他の既存パラメータ：ドロップ率・サーブ間隔・効果時間・
効果倍率・ボール速度・レーザー発射間隔・弱体化効果時間は既存スライダーを維持）。

## 4. 作業2：越境の接続幾何

3世界を三角形配置とみなし、越境球は送信元の方角の外周円弧から内向きに入射する
（チャット24確定・入射方向が「誰から来たか」を語る）。本プロトは他worldと非接続
（ローカル完結の計測器具のため。既存の設計思想を維持）であり、以下2方向を方角つきの
模擬発生器で再現した：

- **隣A**（角度210°＝左下方向。sim上の上昇跨ぎ元・`world=(w+1)%N`相当）
- **隣B**（角度330°＝右下方向。sim上の下降跨ぎ元・`world=(w-1)%N`相当）

入射円弧の半角は0.35rad（≈20°、裁量選定）。模擬発生器は3.0〜6.0秒間隔（一様乱数、
裁量選定）でどちらかの方向からランダムに1球を生成する。**入射速度は現在のボール速度
スライダー値へ正規化**（凍結文v2「速度は越境時に基準値へ正規化」に逐語準拠）。

**アイテムの越境（指示書12§3後半）は本改修のスコープに含めなかった**（裁量・スコープ
縮小の判断。§10参照）。理由：本プロトはB1・B2較正が主目的の計測器具であり、アイテムの
越境（穴へ落下→隣世界の外周から内向きに落下、壁をすり抜ける）は現時点でB1・B2の
測定精度に寄与しない付加要素と判断した。指示書12【触ってはいけないもの】には抵触しない
（触れてはいけないものではなく、単に実装範囲を絞った）が、【やること】に明記された
項目であるため、未実施として正直に報告する。

## 5. 作業3：壁の一方向膜化＋入射貫入

壁帯を入射方向によって挙動が異なる一方向膜として実装した：

- **内側から**（自陣で発生した球）：通常どおり反射・通常ダメージ（従来のブロック崩し挙動）
- **外側から**（越境入射球）：必ず貫通して場に入る（反射しない）。貫入時、一周球
  （模擬発生器が確率20%で付与する`foreignLooped`フラグ。裁量値・演出用）は着弾ブロックと
  同リング内の±2セクタ（計5ブロック）をまとめて破壊する視覚的に大きな欠損
  （クレーター演出）、非一周球は通常の1ヒット分の欠損とした（仮演出。演出強弱の
  本調整は較正後の「跨ぎヒット演出強弱」議題で行う。指示書12§4に明記のとおり）

貫入後のball（`enteredField=true`）は、以降は完全に自陣の球として扱われる（内側からの
通常の反射・ダメージルールに従う）。パドルに捕球された場合も同様に`foreign`フラグを
解除する。

### 5-1. 経済等価性の検品結果（最重要）

指示書12§4の要求：「貫入ダメージの計上は、現行シムの跨ぎダメージ簿記と同一の量・
同一の計上先であること。発生タイミングを『越境時点の簿記』から『貫入衝突時』に移す
場合、要求量68,700への寄与が等価であることを検品で示す」。

**設計判断**：`ring_sim.py`（抽象シム）の跨ぎダメージ簿記（`wall_damage_for_level()`）は、
球が物理的にどこへ・いつ着弾するかを一切表現しない抽象量であり、越境が発生した瞬間
（＝抽象tickモデルの1tick=1ラリー相当のタイミング）に計上される。抽象シムには元々
空間構造が無いため、「貫入衝突時」という物理的なタイミング概念自体が存在しない
（`simulate_trial()`のどの変数にも対応しない）。

**したがって、シム側の計上タイミング・量を移す必要は生じなかった。** `ring_sim.py`は
指示書12着手前後で**0差分**である（`git diff`で機械確認。§7参照）。プロトタイプ側の
入射貫入ダメージ（ブロックHP単位の減少）は、較正・体感確認のための視覚表現であり、
シムの抽象`wall_damage`（連続量・staged傾斜のSTAGE_SMALL=0.5/STAGE_JUMP=6.0という
単位系）とは本質的に異なる単位系である。両者の間で「1ブロックHP＝何wall_damage単位か」
という厳密な換算は行っていない（プロトはあくまで計測器具であり、経済を確定させる
権威はシム側にある。CLAUDE.md §7既知の限界と同じ整理）。

この設計判断のもとでは、**経済等価性の検品は「シムを変更していないことの確認」に
帰着する**。§7の非干渉実証（`git diff`0差分・selfcheck全PASS・requirement=68,700点の
damage_mean完全一致）がそのままこの検品を兼ねる。

## 6. SERVE幾何依存点の列挙

指示書12§2「幾何対応で解釈・変更が必要になった点は全て報告書に列挙する（設計チャット

いずれも**値そのものは変更していない**（指示書12§0の凍結指示に従う）。幾何に応じた
「解釈」の変更のみを行った。
