## 1. 凍結文（現行・v2）

確定：設計チャット19（作家判断・凍結への改訂・2026-07-29）

> **盤面スコープ原則（凍結文 v2）：**パワーアップは全て「自陣の場」に属する効果とし、自陣内にある全ての球（越境してきた球を含む）に無差別に適用され、球が自陣を出た瞬間に効果は残らない（速度は越境時に基準値へ正規化）。効果が球そのものに恒久付着すること、越境挙動を変えることは引き続き禁止。球の**数**に触れるのはマルチボールだけであり、その唯一性が反転1の手がかりとして機能する。

**改訂理由（記録）**：球側効果の採用にあたり、効果を「場」に属させることで越境の縫い目
（強化状態の漏出・切断）を構造的に消し、自球と越境球の挙動差をゼロにして偽装を強化するため。
手がかりは「球の物理に触れる唯一の例外」から「球の数に触れる唯一の例外」へ純化された。

**改訂履歴**：旧版（パドル側限定原則・handoff_設計チャット18 §1 決定⑥、作家判断・2026-07-29）は
`docs/新PJ/archive/新PJ_第3案_凍結文_パドル側限定原則_旧版_2026-07-29.md` に逐語保存済み。
旧版と現行版の違いは「パワーアップが球側に一切触れない（旧）」から
「パワーアップは場に属し、球側にも無差別適用されるが恒久付着・越境挙動変更はしない（新）」
への転換。マルチボールが球の**数**に触れる唯一の例外、という手がかり構造自体は両版で維持。

## 9. SERVE_CAP関連定数一覧（指示書04・シミュ内部定数の読み出し）

出所：`sim/ring_structure/ring_sim.py`（読み取りのみ。コード変更なし）。
これらは**シミュレーション内部で使われている現在値**であり、§6「未設定リスト」の
「SERVE_CAP（設計側承認値）」とは別物。設計側の最終値はまだ承認されておらず、
以下はあくまで指示書01〜03のシミュレーションが暫定的に使ってきた値。

| 変数名 | 現在値 | コード上の役割 |
|---|---|---|
| `SERVE_CAP` | `3` | リング全体の同時最大球数の基準値。実際の上限は`N * SERVE_CAP`（世界あたりの「公平配分」の目安値でもある）。`ring_sim.py:75` |
| `SERVE_INTERVAL` | `40`（tick） | `serve_mode="interval"`（間隔制限サーブ）時の投入間隔。この値のtick数ごとに1回だけ供給フェーズが走る。`ring_sim.py:76` |
| `max_total_balls`（ローカル変数） | `N * SERVE_CAP` | `simulate_trial()`内で毎試行算出される、リング全体の同時球数の実際の上限。この値に達すると新規投入は止まる（越境による流入は別枠でカウントされ、この上限を超えない設計。指示書01で発見・修正した「world単位の上限チェックが越境流入を防げない」バグの回避策）。`ring_sim.py:172` |
| `OVERFLOW_THRESHOLD` | `SERVE_CAP`（＝`3`） | 「球過多」の判定閾値：ある世界の同時球数がこの値以上の時間割合を集計する。`ring_sim.py:78` |
| `STARVE_THRESHOLD` | `0` | 「球涸れ」の判定閾値：ある世界の同時球数がこの値以下の時間割合を集計する。SERVE系そのものではないが供給バランスの対概念として関連が深いため併記。`ring_sim.py:77` |
| `serve_mode`（定数ではなく操作変数） | `"inf"` / `"interval"` | `"inf"`＝供給上限（`max_total_balls`）に達するまで毎tick投入し続ける無制限供給。`"interval"`＝`SERVE_INTERVAL`tickごとにしか投入しない間隔制限供給。`ring_sim.py:186-196` |

**関連する既知の設計メモ**（指示書01報告書より）：
供給上限は「world単位」ではなく「リング全体の総数」で管理されている。これは
指示書01較正時に見つかったバグ（world単位の上限チェックが越境流入を素通りし、
球数が際限なく増殖する）の修正結果であり、**設計側でSERVE_CAPの承認値を検討する際は
「1世界あたりの上限」ではなく「リング全体の総数上限（= N×世界あたり目安値）」という
現在の実装構造を前提にする必要がある**（世界単位の独立した上限にしたい場合は、
越境時の流入制御を別途設計する必要があり、指示書01のバグと同じ暴走を再現しないよう
注意が要る）。
